# 新 VPS 安装恢复与验收修订

基于 `d379256`。保留已提交的动态 Swap 总目标和原生模块编译并行数逻辑，不将 Next.js 的所有内部并行行为误称为已经受这些变量控制。

## 本轮改动

1. **区分构建与部署成功。** 已有构建但缺少服务时继续部署 systemd；已有服务校验目录与 Linux 用户；匹配但未运行的服务尝试启动；活动服务不停止或重启。最终同时验证服务活动、`/api/health` 和管理员/桌面登录记录。失败明确返回非零退出码。
2. **模块与阶段错误。** 报告 START/SUCCESS/FAILED、模块名、退出码和日志路径。安装阶段记录在 `/var/lib/webdesktop-deploy/status`，不含密码。补充 Node 下载、npm、构建、Claude 和数据库故障类别提示，数据库连接字符串、密码和 SQL 保持隐藏。
3. **独立资源预检查。** 无论 Swap 是否启用，都检查根与用户主目录文件系统可用空间；少于 8 GiB 警告。端口 3000 只能为空闲，或由匹配的活动服务在回环地址监听，外来进程不会被终止。创建新 Swap 前检查文件系统兼容性；已有 Swap 处理保留原安全策略。
4. **完整状态查询。** 显示 CPU、内存、磁盘、Swap、源码提交、安装阶段、systemd 单元位置/绑定/开机启用、构建清单、依赖锁、HTTP/数据库/登录、输入法配置和启动入口状态。默认查询不安装、不启动或重启应用，不打印环境文件或服务单元内容。
5. **输入法与桌面入口。** 包装器将 Fcitx 启动错误写到用户状态目录，并在 GUI 会话日志中提示。为识别到的包桌面入口生成用户级覆盖，保留原参数与文件占位符；不修改软件包文件、不覆盖用户自定义入口。未识别入口或保留的自定义入口需要人工核对。
6. **可选源码固定。** `--commit` 接受完整 Git SHA；仅首次克隆时检出该提交。已有源码不匹配时拒绝操作，避免把重复安装变成隐式升级。
7. **可选 GUI 冒烟测试。** `check.sh --gui-smoke` 创建临时 Xvnc/Openbox/Chromium/Fcitx 会话；隔离配置副本与浏览器 profile，清理自己的子进程。仍使用应用当前的 Chromium 兼容参数，不能据此宣称浏览器沙箱已经验证或启用。

## 如何在 VPS 验收

```bash
sudo bash webdesktop-deploy/install.sh
sudo bash webdesktop-deploy/check.sh
sudo bash webdesktop-deploy/check.sh --gui-smoke
```

接着人工验证网页桌面与管理员登录、Claude 启动/登录、Ctrl+Space 切换以及实际输入中文，并重启 VPS 后再次检查服务。中文候选/输入效果、Claude 账号可用性与 ARM64 安装包需要真实环境，脚本和容器测试不能代替。

首次安装或中断续装可使用默认模式；`--mode install` 也允许继续已有构建的服务部署。`--mode repair` 要求已有构建，会恢复匹配但未运行的服务，所以不再承诺保持手工停止的服务不启动。在线升级、自动备份/版本切换/回滚留待 V2。Cloudflare Tunnel、域名、代理和 Windows CLI 继续独立。

## 验证边界

本地回归覆盖中断后缺少服务、错误目录/用户、服务启动失败、健康失败、登录未就绪、不改写原应用、模块退出码、磁盘告警、端口冲突、桌面参数保留及数据库错误脱敏。新增 Debian 12 容器脚本回归任务，保留原 Ubuntu 构建任务；它们需要提交推送后才会运行。

尚未连接真实 Debian VPS 执行完整安装或 GUI 测试，不把生成脚本、模拟服务测试或 CI 配置视为正式 V1 验收。APT 更新仍可能重启 PostgreSQL 等系统组件，恢复模式不是整台 VPS 的不停机保证。
